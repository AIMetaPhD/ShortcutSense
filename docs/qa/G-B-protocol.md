# G-B：真机菜单点击 Spike 协议

**目的**：用一个可复核的数字，回答「鼠标点击菜单项能否被可靠识别」。
**结论只有两种**：达到门槛 → 自动 Learn 可用；达不到 → 立即降级为 ManualMark，不再钻研底层 API。

**执行者**：必须在 Mac 前操作鼠标的人（Owner 或能访问该 Mac 桌面的人）。
**耗时**：约 8 分钟。

---

## 门槛（来自项目负责人裁定）

| 指标 | 门槛 |
|---|---|
| Finder 静态菜单命中 | 点 7 次，≥6 次识别为 `AXMenuItem` 且标题安全 |
| Chrome 静态菜单命中 | 同上 |
| 悬停后取消 | 10 次，误报 **0** |
| 点击网页正文/按钮 | 20 次，误报 **0** |
| 动态项（最近文件、窗口名） | 绝不入库，且被计数为 rejected |

**这是小样本工程放行门槛，不是统计学可靠性证明。**

---

## 步骤

### 1. 启动测量

在 Mac 的终端里执行（**不要**通过 SSH，否则权限会归因给 sshd）：

```bash
open -a /Applications/ShortcutSense.app --args --menu-spike 480
```

计时 8 分钟。期间不要关闭应用、不要退出。

### 2. Finder（约 2 分钟）

1. 打开一个 Finder 窗口，让它在前台
2. 点顶部 **文件** 菜单 → 选 **新建 Finder 窗口**，重复 **7 次**
   （每点一次会新开一个窗口，可以随手关掉）
3. 另外：把鼠标移到 **编辑** 菜单上悬停 3 秒，然后点空白处取消 —— 重复 **5 次**
4. 再点 Finder 窗口的空白区域 **10 次**（非菜单点击）

### 3. Chrome（约 2 分钟）

1. 打开 Chrome，让它在前台
2. 点 **文件** 菜单 → **新建标签页**，重复 **7 次**
3. 悬停 **书签** 菜单后取消，重复 **5 次**
4. 在网页正文里点击文字、按钮、链接，重复 **10 次**

### 4. 你最常用的那个生产力 App（约 1 分钟）

任选一个（Xcode / Slack / 备忘录 / 你的编辑器）：
1. 点它的一个静态菜单项 **7 次**（例如「新建」「保存」）
2. 悬停一个菜单后取消 **5 次**

### 5. 收集结果

时间到后应用会自动退出并写报告。取回：

```bash
cat ~/Library/Application\ Support/ShortcutSense/menu-spike-report.json
```

或者直接告诉 Claude「跑完了」，Claude 会通过 SSH 读取。

---

## 判读

| 报告字段 | 含义 |
|---|---|
| `staticHits` | 成功识别为静态菜单命令的次数 |
| `rejectedDynamic` | 识别为菜单项但标题像用户数据、已被拒绝的次数 |
| `nonMenuClicks` | 未被识别为菜单项的点击（页面正文、按钮、空白） |
| `perBundle.<id>.staticHits` | 每个 App 的命中数 |

**通过条件**：每个目标 App 的 `staticHits` ≥ 6，且 `rejectedDynamic` 中没有任何一条来自动态项被误存。

如果 `nonMenuClicks` 很高但 `staticHits` 为 0，说明命中失败 → 降级 ManualMark。

---

## 无论结果如何都不会做的事

- 不会把窗口标题、文件名、网页内容写进数据库
- 不会为了「跑通」而放宽 `AXMenuCodec.isSafeStaticTitle`
- 不会因为一次不理想的样本就反复重测直到数字好看
