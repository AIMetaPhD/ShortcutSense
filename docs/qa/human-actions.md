## 必做（3 项）

### 1. 操作新 UI 10–15 分钟，让真实数据流经各页面

**为什么**：六个页面全部绑定真实数据库，但从未有人在 GUI 里点过。我现在能证明「编译通过、191 项测试通过、应用能启动」，不能证明「界面上的数字是对的、点 Apply 真的注册了热键」。

**怎么做**：
1. 点菜单栏的 **⌘ 图标** → 应该弹出紧凑面板（能看到今日按键数、三个小指标、两个按钮）
2. 点 **打开仪表盘 / Open Dashboard** → 弹出独立窗口
3. 依次点左侧六项：**今日 / 快捷键 / 推荐 / 冲突检查 / 每周回顾 / 设置**（也可用 ⌘1…⌘6）
4. 在 **今日** 页，确认：
   - 顶部蓝色大数字是你的按键总数
   - 下方三张卡：快捷键触发次数、已活跃应用数、已采用热键触发
   - 键盘图形上有键帽被点亮（你按过的 ⌘C/⌘V/⌘Tab 会亮）
   - 下面有活动时间线（7 天柱状图，因为你没开小时级）
   - 应用排行按按键数排序
5. 在 **快捷键** 页，切换「今天 / 7 天 / 30 天」，再用应用下拉筛选
6. 在 **冲突检查** 页，随便改修饰键和按键，看四态结果和来源
7. 在 **设置** 页，确认输入监控和辅助功能都显示「已授权」

**告诉我就行**，我会查库核对。任何异常截图或描述给我。

## 可选（不影响进度）

### 4. 安装完整 Xcode

你只有 Command Line Tools，没有 XCTest。我写了 shim 跑同一批测试源码（191 项已验证，Linux/Mac/CI 一致）。装了 Xcode 后可以直接 `swift test`，多一条验证路径。App Store 装，约 10GB。

### 5. 清理 Mac 上的临时文件

```bash
rm -rf ~/ShortcutSense ~/ss-cert ~/Desktop/finish-cert.command
```

**注意**：删 `~/ss-cert` 会删掉自签名证书，之后构建会退回 ad-hoc 签名，**权限又会因重建失效**。建议留着，除非你要改用 Developer ID。

### 6. Apple Developer ID（年费）

有了才能公证，用户安装时不必走「仍要打开」。现在的自签名证书已解决权限稳定性，Gatekeeper 那关仍会拦。

## 我判断你需要知道的风险

1. **自签名证书私钥在 `~/ss-cert/ss.keychain`，密码 `shortcutsense`**。这是本地开发便利，不是发布级安全。正式发布应改用 Developer ID。

2. **Muse 只能做静态审阅**。三位都是无人值守 Linux worker，没有 macOS 桌面。所有 GUI 验收只能你本人，或另一个有 Mac 桌面的人做。这一轮 Muse-2 审了 UI 代码，找出 6 个问题（D-029…D-034），其中两个是「查询失败却显示成好消息」——已修。

3. **公开仓库前必须再跑一次脱敏检查**。现在是干净的（工作区、历史、提交信息三处都验过），但后续任何提交都可能带进新路径或用户名。命令在 `Tools/sanitize-history.md`。

4. **hourly 小时级采集默认关闭**。这是按 v2.1 数据合同的保守默认。开启后「今日」页会显示 24 小时时间线而不是 7 天柱状图。设置页有开关和说明。
