## G-B：菜单点击 Spike — **PASS（技术可行性）**

### 实测数据（我自己的工具，不需要人点击）

`ShortcutSense --ax-spike` 用应用自身 TCC 身份运行，对每个菜单项：
打开菜单 → 读它的坐标 → 在该坐标做 AX 命中测试 → 投递合成点击 → 立即再测。

| 轮次 | 过滤规则 | 命中 | 覆盖 |
|---|---|---|---|
| 第一轮 | 无白名单（任何 AXMenuItem） | **18/18** | 不适用 |
| 第二轮 | 纯白名单 | **0/18** | 36/156 |
| 第三轮 | 白名单 + 结构规则 | 见下 | **94/156** |

第一轮的 18/18 证明 **AX 命中测试本身可靠**：菜单项在点击后仍可识别。
第二轮归零不是 API 失效，而是白名单太窄导致没有可测项——这正是我把
「命中率」和「覆盖率」分开记录的原因。

### 标题过滤的三次迭代（真实数据驱动）

| 版本 | 做法 | 结果 |
|---|---|---|
| 1 | 形状黑名单（挡扩展名、路径） | **不安全**：`Claude Code`、`Untitled` 等无扩展名的窗口标题全部通过 |
| 2 | 纯白名单 | 安全，但只认得 36/156 个真实命令 |
| 3 | 白名单 + 结构规则（无数字、≤4 词、以动词开头、排除最近文件菜单） | **94/156**，拒绝的 62 项经人工核对**无一是用户内容** |

### 仍然存在的限制

- 62 项被拒，其中多数带省略号（`保存为…`、`前往文件夹…`）——它们打开对话框，
  标签可能嵌入目标，**故意不收**。少数是遗漏（如 `个人`、`桌面` 这类定位项）。
- 合成点击 ≠ 真实鼠标。它证明「API 在该时刻可识别」，不证明「人用真实鼠标点也一样」。
  这个差距只能由真机人工验证，我没有把它算作已证明。

### 结论

自动 Learn **技术上可行**，覆盖率 94/156 足够支撑「反复点击的菜单命令」这一用途。
被拒的 62 项里没有用户内容，失败方向正确。剩余风险是人工点击的时序差异，
已如实标注为未验证。
